# PS2 в браузере

Статический сайт, на котором можно запустить **свой** образ игры PlayStation 2 в браузере. Движок — экспериментальная WebAssembly-сборка эмулятора [Play!](https://github.com/jpd002/Play-) (тот же порт, что на [playjs.purei.org](https://playjs.purei.org/)).

В репозитории нет образов игр и нет BIOS. Сайт не принимает файлы на сервер: выбранный ISO или CHD читается только в вашем браузере.

## Адрес

После включения GitHub Pages сайт открывается здесь:

**https://alekseichmsk.github.io/ps2-web/**

Пока Pages не включены, эта ссылка не работает.

## Как включить GitHub Pages

Это ручной шаг. Одного пуша в репозиторий недостаточно, пока в настройках не выбран источник «GitHub Actions».

1. Влейте изменения в ветку `main`. Workflow [`.github/workflows/pages.yml`](.github/workflows/pages.yml) запускается при push в `main` и по кнопке Run workflow.
2. Откройте **Settings → Pages**.
3. В блоке **Build and deployment** поставьте **Source: GitHub Actions** (не «Deploy from a branch»).
4. Дождитесь зелёного прогона **Deploy GitHub Pages** на вкладке Actions.
5. Откройте https://alekseichmsk.github.io/ps2-web/

Если первый деплой упал с ошибкой окружения `github-pages`, ещё раз выберите источник GitHub Actions и перезапустите workflow: **Actions → Deploy GitHub Pages → Run workflow**.

Репозиторий должен быть публичным: пользовательский сайт `*.github.io` на бесплатном плане отдаёт только публичные репозитории.

## Как играть

1. Откройте сайт в актуальном Chrome или Firefox. Safari на iPhone тоже может запуститься, но работает хуже и медленнее.
2. Дождитесь статуса «Эмулятор готов». При первом заходе страница **один раз перезагрузится**: так сервис-воркер включает `SharedArrayBuffer` (заголовки COOP/COEP, без которых сборка Play! с потоками не стартует). GitHub Pages свои заголовки выставить не умеет, поэтому используется [coi-serviceworker](https://github.com/gzuidhof/coi-serviceworker).
3. Нажмите **«Выбрать образ»** и укажите файл, которым вы владеете легально. Подходят **ISO, CHD, CSO, ISZ, BIN и ELF**. BIOS не нужен. Файл можно перетащить на экран.
4. Первые секунды экран может быть чёрным: эмулятор читает образ кусками и компилирует код игры.
5. Управление — клавиатура, обычный геймпад (Gamepad API) или кнопка **«Экранный геймпад»**. **«На весь экран»** разворачивает картинку вместе с экранными кнопками.

### Клавиатура

| Кнопка PS2 | Клавиша |
| --- | --- |
| Крестовина | Стрелки |
| Левый стик | F влево, H вправо, T вверх, G вниз |
| Правый стик | J влево, L вправо, I вверх, K вниз |
| Квадрат / крест / треугольник / круг | A / Z / S / X |
| Start / Select | Enter / Backspace |
| L1 L2 L3 | 1 2 3 |
| R1 R2 R3 | 8 9 0 |

Геймпад в браузере ожидается со стандартной раскладкой: нижняя кнопка — крест, правая — круг, левая — квадрат, верхняя — треугольник.

Если игра не стартовала, откройте «Журнал эмулятора». Совместимость неполная даже у настольной версии Play!, а браузерный порт — эксперимент: [список совместимости](https://github.com/jpd002/Play-Compatibility/issues).

## Скорость

На настольном компьютере часть игр идёт играбельно, но это не скорость обычного Play! для Windows, macOS или Linux. Тяжёлые сцены проседают, звук может заикаться, загрузка уровня занимает заметно больше времени.

На телефоне и планшете будет медленно. WebAssembly-сборка с двумя потоками упирается в процессор: ждите низкий кадр/с, нагрев, прожорливость батареи и обрывы звука. Закройте остальные вкладки. Если есть выбор, берите **CHD**: он меньше, и браузеру проще читать его кусками. Не рассчитывайте на мобильную версию как на способ нормально пройти игру.

Большой ISO (несколько гигабайт) на телефоне может просто не открыться из‑за нехватки памяти, даже если файл формально не копируется целиком.

## Что важно знать

- Образ не загружается на сервер и не сохраняется сайтом. После закрытия вкладки он остаётся только у вас на диске.
- Нужен обычный режим браузера, не приватный: в приватном режиме сервис-воркер часто запрещён, и `SharedArrayBuffer` не включится.
- Не открывайте `index.html` двойным щелчком с диска. Нужен адрес `http://` или `https://`.
- Звук появляется после первого нажатия: так браузер разрешает аудио.
- Это порт не всех игр, которые идут в настольном Play!.

## Локальный просмотр

```bash
cd site
python3 -m http.server 8080
```

Откройте http://localhost:8080 . На localhost страница тоже один раз перезагрузится из‑за сервис-воркера.

## Откуда взята сборка эмулятора

В каталоге `site/emulator/` лежат готовые `Play.js` и `Play.wasm` с официального сайта playjs.purei.org (версия вшита в модуль, сейчас `0.77-13-gd44bfa18`). Исходники: <https://github.com/jpd002/Play->. Лицензия эмулятора — `site/emulator/License.txt` (BSD, Jean-Philip Desjardins). Контрольные суммы — `site/emulator/SHA256SUMS`, откуда скачаны файлы — `site/emulator/PROVENANCE.txt`.

Сборка всего Play! в GitHub Actions возможна (`emcmake`, пресет `wasm-ninja`, Emscripten), но это длинная компиляция со всеми подмодулями, и она легко ломается. Для Pages надёжнее хранить тот же готовый веб-артефакт, который уже отдаёт официальный сайт, и проверять его контрольную сумму в workflow.

Обновить сборку:

```bash
./scripts/vendor-play.sh
```

Скрипт заново скачивает `Play.js` и `Play.wasm`, пересчитывает суммы и подставляет версию в `site/app.js`.

Проверка страницы без образа игры (нужны Google Chrome и `puppeteer-core`):

```bash
npm install --prefix scripts puppeteer-core
node scripts/verify-page.mjs
```

Скрипт поднимает сайт, дожидается строки версии Play! и инициализации WebGL, проверяет клавиатуру, экранные кнопки и вызов загрузки диска на пустом файле.
